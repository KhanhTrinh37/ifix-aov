Nghiên cứu này được thực hiện và tài liệu hóa hoàn toàn vì mục đích giáo dục và nghiên cứu bảo mật.

Tác giả không khuyến khích, hỗ trợ, hoặc dung túng việc sử dụng thông tin này để tạo ra các phần mềm gian lận (cheat), phá hoại môi trường trò chơi trực tuyến, hoặc vi phạm bản quyền và chính sách của nhà phát hành.

Tài liệu này cung cấp một phân tích dịch ngược toàn diện về InjectFix của Tencent được triển khai trong Arena of Valor phiên bản 1.60.1.9. Sau đó, chúng ta sẽ đi sâu vào cách ứng dụng thực tế thư viện nguồn mở này cho các dự án Unity cá nhân.

Phần 1: Giải mã các tệp Hotfix

Bước đầu tiên trong quy trình iFix là giải mã các tệp hotfix .bytes.

1.1. Thuật toán giải mã

Hệ thống sử dụng thuật toán AES ở chế độ CBC. Việc giải mã được xử lý bởi lớp System.Security.Cryptography.CryptoStream của framework .NET, cung cấp giao diện dựa trên luồng cho các biến đổi mật mã. Việc thiết lập và khởi tạo luồng giải mã này xảy ra trong hàm tạo của lớp CommonLibs.FileModule.ResDReader.KnowLengthBytesStream.

  • Function: CommonLibs.FileModule.ResDReader.KnowLengthBytesStream..ctor
  • Address: 0x5BF8D24
C# (IDA Pseudo-code) 
// Constructor for KnowLengthBytesStream
public KnowLengthBytesStream(Stream inStream, string resName, ..., bool isEncrypt)
{
    // ...
    if (isEncrypt)
    {
        // 1. Get the AES provider instance. This function also sets the IV.
        m_aesProvider = ResDReader.get_m_aesProvider();

        // 2. Derive the decryption key based on the resource name.
        byte[] mixedKey = ResDReader.GetMixedKey(resName);

        // 3. Set the Key for the AES provider.
        m_aesProvider.set_Key(mixedKey);

        // 4. Create the AES decryptor transform.
        ICryptoTransform decryptor = m_aesProvider.CreateDecryptor();

        // 5. Wrap the original (encrypted) stream with a CryptoStream.
        this.m_cryptoStream = new CryptoStream(inStream, decryptor, CryptoStreamMode.Read);
    }
}

Phần 2 & 3: Cấu trúc tệp và Máy ảo VM

Tệp .dec sau giải mã chứa Magic Number, Tên Bridge, Các kiểu bên ngoài, Bytecode Phương thức, v.v. Máy ảo (Virtual Machine) của iFix duyệt qua từng Opcode (ví dụ StackSpace, Ldarg, Add) để thực thi logic vá lỗi trên một ngăn xếp ảo. Toàn bộ logic này kế thừa từ thiết kế mã nguồn mở InjectFix.

Phần 4: Tạo Hotfix Bytecode (Lý thuyết)

Bằng cách viết script Python đóng gói các lệnh Opcode (CallVirt, Mul, Ret), ta có thể biên dịch ra file .dec chứa bytecode vá lỗi (ví dụ nhân 3 một chỉ số trong game), sau đó mã hóa lại thành .bytes để tải. Tuy nhiên, quy trình này rất phức tạp. Ở phần tiếp theo, chúng ta sẽ xem cách InjectFix tự động hóa quy trình này.

Phần 5: Sử dụng InjectFix trong thực tế

Thay vì phải biên dịch thủ công bytecode như phần 4, framework Tencent/InjectFix cung cấp công cụ tự động hóa quá trình này cho Unity.

5.1. Cơ chế hoạt động của InjectFix

InjectFix hoạt động bằng cách can thiệp vào giai đoạn biên dịch IL của Unity (sử dụng Mono.Cecil). Nó thay đổi các hàm gốc, chèn một đoạn mã kiểm tra (if-check). Tại runtime, nếu có bản vá (Patch) được tải, luồng thực thi sẽ nhảy vào Virtual Machine (VM) của InjectFix để chạy mã IL mới thay vì mã cũ.

5.2. Các Attribute cốt lõi

  • [IFix.Patch]: Gắn lên hàm cần sửa đổi. Script của InjectFix sẽ dịch hàm này sang mã IL và đóng gói vào file patch.
  • [IFix.Interpret]: Thêm hàm mới hoặc Class hoàn toàn mới vào bản vá (không tồn tại trong file gốc).
  • [IFix.CustomBridge]: Cầu nối cần thiết khi mã trong VM cần giao tiếp với Delegate/Event của C# gốc bên ngoài.

5.3. Demo quy trình vá lỗi (Hotfixing)

Giả sử chúng ta có một lớp quản lý máu của nhân vật, và hàm tính toán đang bị lỗi:

C# (Sửa lỗi logic) 
public class HealthSystem 
{
    // Đánh dấu hàm cần vá bằng Attribute của IFix
    [IFix.Patch]
    public void TakeDamage(int damage) 
    {
        // Lỗi gốc: health += damage; (cộng nhầm máu thay vì trừ)
        // Mã sau khi sửa:
        this.health -= damage; 
        
        if (this.health < 0) 
            Die();
    }
}

Sau khi sửa mã, bạn chọn Menu InjectFix -> Fix All trong Editor. InjectFix sẽ phân tích hàm TakeDamage mới, chuyển nó thành file patch.bytes. Bạn đẩy file này lên Server. Dưới Client Unity, bạn tải file về và gọi lệnh nạp:

C# (Nạp bản vá tại Runtime) 
using IFix.Core;
using System.IO;

public class HotfixManager : MonoBehaviour 
{
    void Start() 
    {
        string patchPath = Path.Combine(Application.persistentDataPath, "patch.bytes");
        
        if (File.Exists(patchPath))
        {
            using (FileStream fs = new FileStream(patchPath, FileMode.Open))
            {
                // Nạp bytecode vá lỗi vào Máy ảo (Virtual Machine)
                PatchManager.Load(fs);
            }
        }
    }
}

Với phương thức này, các nhà phát triển game có thể khắc phục các lỗi nghiêm trọng (Critical Bugs) hoặc cập nhật logic sự kiện ngay lập tức mà không cần người dùng phải tải lại toàn bộ bản cập nhật ứng dụng từ App Store/Google Play.
