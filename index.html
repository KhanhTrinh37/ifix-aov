1.2. Trích xuất Key và IV

Khóa (16-bytes)

Khóa được tính toán động dựa trên tên tệp[cite: 1]. Quá trình này bao gồm hai hàm chính[cite: 1]:

Bước 1: Băm tên tệp

  • Function: CommonLibs.FileModule.ResDReader.GetStrUpperHash[cite: 1]
  • Address: 0x5BF7F68[cite: 1]
  • Logic: Băm tên tài nguyên viết hoa bằng công thức: hash = (hash * 31) + character[cite: 1].
C# (IDA Pseudo-code) 
public static uint GetStrUpperHash(string inAssetName)
{
    uint hash = 0;
    foreach (char c in inAssetName.ToUpper())
    {
        hash = (hash * 31) + c;
    }
    return hash;
}

Bước 2: Trộn với Khóa Cơ sở (Base Key)

  • Function: CommonLibs.FileModule.ResDReader.GetMixedKey[cite: 1]
  • Address: 0x5BF805C[cite: 1]
  • Logic: Lấy mã băm từ bước trước và thực hiện XOR từng byte với một Khóa Cơ sở cố định: 99 64 b1 b0 6b 03 8d 7f b7 7d b6 a7 54 90 8b 73[cite: 1].
C# (IDA Pseudo-code) 
public static byte[] GetMixedKey(string resName)
{
    uint hash = GetStrUpperHash(resName);
    byte[] keyBytes = (byte[])mRawKeys.Clone(); // mRawKeys holds the base key

    for (int i = 0; i < keyBytes.Length; i++)
    {
        // XOR each byte of the key with a byte from the hash
        keyBytes[i] ^= (byte)(hash >> ((i & 3) * 8));
    }
    return keyBytes;
}

IV (16-bytes)

IV là một giá trị tĩnh[cite: 1]. Sau khi sử dụng trình gỡ lỗi (debugger), đã xác nhận rằng IV là 16 byte 0[cite: 1].

  • Function: CommonLibs.FileModule.ResDReader.get_m_aesProvider[cite: 1]
  • Address: 0x5BF82D4[cite: 1]
  • Logic: Hàm này tạo phiên bản AesCryptoServiceProvider nếu nó chưa tồn tại và thiết lập thuộc tính IV của nó[cite: 1].
C# (IDA Pseudo-code) 
private static AesCryptoServiceProvider get_m_aesProvider()
{
    if (m_aesProvider == null)
    {
        m_aesProvider = new AesCryptoServiceProvider();
        m_aesProvider.set_Mode(CipherMode.CBC);
        m_aesProvider.set_IV(mIV); // Sets the static IV, which is 16 zero bytes
    }
    return m_aesProvider;
}

1.3. Script Python

Kịch bản này triển khai logic giải mã[cite: 1]. Một số tệp có header magic 3 byte 22 4A 67 trước dữ liệu được mã hóa[cite: 1].

Python 
from Crypto.Cipher import AES
from Crypto.Util.Padding import pad, unpad
import os

MAGIC = bytes.fromhex("22 4A 67")

def _key(name: str) -> bytes:
    h = 0
    for ch in name:
        c = ord(ch)
        if 97 <= c <= 122:
            c -= 32
        h = ((h * 31) + c) & 0xFFFFFFFF
    
    k = bytearray(bytes.fromhex("99 64 b1 b0 6b 03 8d 7f b7 7d b6 a7 54 90 8b 73"))
    k0, k1, k2, k3 = (h & 0xFF, (h >> 8) & 0xFF, (h >> 16) & 0xFF, (h >> 24) & 0xFF)
    
    for i in range(len(k)):
        k[i] ^= (k0, k1, k2, k3)[i & 3]
    
    return bytes(k)

def decrypt(name: str) -> bytes:
    key = _key(name)
    if not os.path.exists(f"{name}.bytes"):
        print(f"File {name}.bytes not found!")
        return b""

    with open(f"{name}.bytes", "rb") as f:
        data = f.read()

    off = 3 if data[:3] == MAGIC else 0
    ct = data[8:]
    cipher = AES.new(key, AES.MODE_CBC, b"\x00" * 16)

    try:
        decrypted_data = cipher.decrypt(ct)
        pt = unpad(decrypted_data, AES.block_size)
    except (ValueError, KeyError):
        raise ValueError("Invalid padding or wrong key/iv")

    with open(f"{name}.dec", "wb") as f:
        f.write(pt)
    return pt

def encrypt(name: str) -> bytes:
    key = _key(name)
    if not os.path.exists(f"{name}.dec"):
        print(f"File {name}.dec not found!")
        return b""

    with open(f"{name}.dec", "rb") as f:
        pt = f.read()

    original_len = len(pt)
    pt_padded = pad(pt, AES.block_size)
    cipher = AES.new(key, AES.MODE_CBC, b"\x00" * 16)
    ct = cipher.encrypt(pt_padded)

    hdr = (0).to_bytes(4, "little") + original_len.to_bytes(4, "little")

    with open(f"{name}.bytes", "wb") as f:
        f.write(hdr + ct)

    with open(f"{name}.bytes", "r+b") as f:
        f.seek(0)
        f.write(MAGIC)

    return ct

Phần 3: Cấu trúc bên trong Máy ảo (Virtual Machine)

Bytecode của iFix được diễn dịch bởi một Máy ảo tùy chỉnh[cite: 1]. Công cụ thực thi này được dẫn xuất từ kiến trúc của InjectFix của Tencent, được thiết kế để phân tích động và chạy các lệnh IL tại runtime mà không cần cập nhật toàn bộ ứng dụng[cite: 1].

3.2. Ví dụ về xử lý Opcode

StackSpace

Lệnh này được xử lý một lần ở đầu hàm Execute để thiết lập khung ngăn xếp[cite: 1].

  • Mục đích: Định nghĩa độ sâu ngăn xếp tối đa và số lượng biến cục bộ cho một phương thức[cite: 1].
  • Toán hạng: Chứa max_stack (16 bit thấp) và locals_cnt (16 bit cao)[cite: 1].
C (IDA Pseudo-code) 
// ... at the very beginning of the Execute function
if (pc->fields.Code != 146) // pc is the first instruction
{
    // ... throw InvalidProgramException
}
virtualMachine = v15;
Operand = pc->fields.Operand; // pc->fields.Operand is the operand of StackSpace

v18 = argumentBase - evaluationStackBase;
if ((int)(v18 + argsCount + (Operand >> 16) + (unsigned __int16)Operand) >= 10241) // Check for stack overflow
{
    // ... throw StackOverflowException
}
// ... further initialization using Operand's values

Giải thích: Trước khi bất kỳ lệnh nào khác được thực thi, hàm Execute xác thực rằng lệnh đầu tiên là StackSpace[cite: 1]. Sau đó, nó trích xuất kích thước ngăn xếp tối đa và số lượng biến cục bộ từ toán hạng của nó[cite: 1]. Thông tin này rất quan trọng để thiết lập khung ngăn xếp của phương thức và thực hiện các kiểm tra tràn ngăn xếp ban đầu[cite: 1].

Ldarg: Tải Đối số

Đẩy một đối số của phương thức lên evaluation stack[cite: 1].

  • Opcode: case 164:[cite: 1]
C (IDA Pseudo-code) 
// Ldarg instruction
// v1187 là 'argumentBase'
// v20->fields.Operand chứa chỉ số đối số (argument index)
// v19 là con trỏ ngăn xếp ('evaluationStack')

IFix_Core_VirtualMachine__copy(
    virtualMachine,
    evaluationStackBasea,
    v19++, // Đích trên ngăn xếp (và tăng con trỏ ngăn xếp)
    &v1187[v20->fields.Operand], // Đối số nguồn từ mảng đối số
    managedStack,
    ...);
++v20; // Chuyển sang lệnh tiếp theo
continue;

Giải thích: Đoạn mã này sao chép một giá trị từ mảng argumentBase (tại chỉ số được chỉ định bởi toán hạng operand) lên đỉnh của evaluation stack[cite: 1]. Con trỏ ngăn xếp v19 sau đó sẽ được tăng lên[cite: 1].

Add: Phép cộng

Lấy (pop) hai giá trị ra khỏi ngăn xếp, cộng chúng lại và đẩy (push) kết quả trở lại ngăn xếp[cite: 1].

  • Opcode: case 80:[cite: 1]
C (IDA Pseudo-code) 
// Add instruction

if (v19 == (IFix_Core_Value_o*)&dword_18)

case 1: // Long (Số nguyên 64-bit)

        sub_94DC8A0("L_582");
    *(_QWORD*)&v537->fields.Value1 += *(_QWORD*)&v19->fields.Value1; // Cộng các giá trị long
    ++v20;
    break;

case 2: // Float (Số thực)
    if (!v19)
        sub_94DC8A0("L_595");
    *(float*)&v537->fields.Value1 = *(float*)&v537->fields.Value1 + *(float*)&v19->fields.Value1; // Cộng các giá trị float

Giải thích: Mã trước tiên sẽ giảm con trỏ ngăn xếp (v19)[cite: 1]. Sau đó, nó kiểm tra Type của giá trị tại đỉnh ngăn xếp mới (v537)[cite: 1]. Dựa trên kiểu dữ liệu (số nguyên, số long, số thực float,...), nó thực hiện phép cộng thích hợp với giá trị nằm ở trên đỉnh trước đó, rồi lưu kết quả ngược lại vào v537[cite: 1].

Phần 4: Tạo Hotfix Bytecode

Với việc hiểu rõ định dạng tệp và logic của VM, bây giờ tôi có thể xây dựng một hotfix tùy chỉnh[cite: 1]. Mục tiêu của tôi là sửa đổi CameraSystem.GetZoomRate để trả về gấp 3 lần giá trị ban đầu[cite: 1].

4.1. Chiến lược Patch (Vá lỗi)

Tôi cần tạo một tệp nhị phân (.dec) chứa[cite: 1]:

  1. Extern Types: CameraSystem và System.Single[cite: 1].
  2. Method Body: Một chuỗi các lệnh để triển khai return this.get_ZoomRateFromAge() * 3.0f;[cite: 1].
  3. Fix Info: Ánh xạ phương thức mới của tôi với GetZoomRate[cite: 1].

4.2. Logic của Opcode

Chuỗi assembly sau[cite: 1]:

  • StackSpace (146, 2): Khởi tạo kích thước ngăn xếp bằng 2[cite: 1].
  • Ldarg.0 (164, 0): Tải this[cite: 1].
  • CallVirt (122, token): Gọi get_ZoomRateFromAge[cite: 1].
  • Ldc_I4 (143, 3): Đẩy số nguyên 3 vào[cite: 1].
  • Conv.R4 (58, 0): Chuyển đổi 3 sang float[cite: 1].
  • Mul (3, 0): Nhân kết quả[cite: 1].
  • Ret (173, 1): Return (Trở về)[cite: 1].

4.3. Script Python

Tôi đã viết kịch bản Python này để tạo trực tiếp tệp nhị phân chưa được mã hóa (HeroSkin_1.dec), bỏ qua sự cần thiết của trình biên dịch chính thức[cite: 1].

import struct

def w_str(f, s):
    data = s.encode('utf-8')
    l = len(data)
    while l >= 0x80:
        f.write(struct.pack('B', (l & 0x7F) | 0x80))
        l >>= 7
    f.write(struct.pack('B', l))
    f.write(data)

with open("HeroSkin_1.dec", 'wb') as f:
    # 1. Header Magic
    f.write(struct.pack('<Q', 0x1FD45F460E2CDBD0))

    # 2. Bridge Name
    w_str(f, "IFix.ILFixInterfaceBridge, Project_d, Version=0.0.0.0, Culture=neutral, PublicKeyToken=null")

    # 3. Extern Types
    types = [
        "CameraSystem, Project_d, Version=1.0.0.0, Culture=neutral, PublicKeyToken=null",
        "System.Single, mscorlib, Version=4.0.0.0, Culture=neutral, PublicKeyToken=b77a5c561934e089"
    ]
    f.write(struct.pack('<i', len(types)))
    for t in types:
        w_str(f, t)

    # 4. Methods (Payload)
    # Logic: return 3 * get_ZoomRateFromAge()
    ops = [
        (146, 2),    # StackSpace (locals=0, maxstack=2)
        (164, 0),    # ldarg.0
        (122, 65536),# callvirt CameraSystem::get_ZoomRateFromAge
        (143, 3),    # ldc.i4 3
        (58, 0),     # conv.r4
        (3, 0),      # mul
        (173, 1)     # ret
    ]

    f.write(struct.pack('<i', 1)) # Num methods
    f.write(struct.pack('<i', len(ops)))
    for code, op in ops:
        f.write(struct.pack('<ii', code, op))
    f.write(struct.pack('<i', 0)) # No exception handlers

    # 5. Extern Methods References
    f.write(struct.pack('<i', 1)) # Count
    f.write(struct.pack('<?i', False, 0)) # is_generic=False, type_id=0 (CameraSystem)
    w_str(f, "get_ZoomRateFromAge")
    f.write(struct.pack('<i', 0)) # param_ids count
    f.write(struct.pack('<4i', 0, 0, 0, 0))

    # 6. Managers info
    w_str(f, "IFix.WrappersManagerImpl, Project_d, Version=0.0.0.0, Culture=neutral, PublicKeyToken=null")
    w_str(f, ", Project_d, Version=0.0.0.0, Culture=neutral, PublicKeyToken=null")

    # 7. Fix Infos (Mapping)
    f.write(struct.pack('<i', 1)) # Count
    # Target: CameraSystem.GetZoomRate -> Patch ID 0
    f.write(struct.pack('<?i', False, 0))
    w_str(f, "GetZoomRate")
    f.write(struct.pack('<i', 0)) # param_ids count
    f.write(struct.pack('<i', 0)) # patch_id

    # 8. New Classes
    f.write(struct.pack('<i', 0))

    print("Done")

4.4. Hoàn thiện Hotfix

Sau khi chạy kịch bản trình tạo, tôi thu được HeroSkin_1.dec[cite: 1]. Sau đó, sử dụng mã mã hóa từ Phần 1.3 để tạo ra HeroSkin_1.bytes và sao chép nó vào thư mục tài nguyên của trò chơi[cite: 1].

Phần 5: Hướng dẫn thực hành chuyên sâu với Tencent InjectFix

Sau khi đã tìm hiểu cách iFix hoạt động bên dưới thông qua dịch ngược và phân tích máy ảo VM ở Phần 1 đến Phần 4, phần này sẽ cung cấp hướng dẫn thực hành kỹ thuật toàn diện: từ nguyên lý chèn mã (IL Weaving), các kịch bản lập trình thực tế trong game (đọc/ghi thuộc tính nhân vật, vị trí, giao diện) cho đến quy trình đóng gói và mã hóa tệp patch .bytes thành phẩm.

5.1. Cơ chế IL Weaving & Hooking của InjectFix

Điểm độc đáo của InjectFix nằm ở chỗ nó giải quyết bài toán hotfix cho môi trường iOS / IL2CPP (AOT - Ahead-Of-Time), nơi hệ điều hành cấm hoàn toàn việc cấp phát bộ nhớ có quyền thực thi mã máy (JIT cấm thực thi bộ nhớ động)[cite: 1]:

  • Giai đoạn Build (IL Weaving): Thông qua thư viện Mono.Cecil, InjectFix quét mã IL của assembly game (Assembly-CSharp.dll) và chèn một đoạn mã rẽ nhánh (Hook Stub) vào đầu mỗi phương thức cần bảo vệ.
  • Giai đoạn Runtime: Khi hàm được gọi, đoạn Stub kiểm tra xem hàm đó đã có bản vá trong máy ảo hay chưa qua WrappersManager.
    • Nếu chưa có bản vá: Tiếp tục chạy mã C# gốc với tốc độ nguyên bản (zero overhead).
    • Nếu đã nạp bản vá: Chuyển hướng toàn bộ tham số và luồng thực thi sang máy ảo VirtualMachine.Execute để thông dịch các bytecode mới[cite: 1].

5.2. Các Attribute cốt lõi & Kỹ thuật mở rộng trạng thái

Để làm việc hiệu quả với InjectFix, lập trình viên cần nắm vững 3 Attribute chính cùng giải pháp mở rộng dữ liệu:

[IFix.Patch]

Đánh dấu phương thức hoặc property getter/setter cần thay thế hoàn toàn logic cũ bằng logic mới.

[IFix.Interpret]

Sử dụng khi viết thêm một lớp (class) mới toanh hoặc method tiện ích mới trong bản vá mà bản build gốc chưa hề có.

[IFix.CustomBridge]

Cầu nối bắt buộc khi truyền delegate (Action, Func, UnityEvent) từ bên trong VM ra C# runtime gốc.

Quy tắc sống còn: Không thể thêm Field vật lý mới vào Class có sẵn

Vì bộ nhớ cấu trúc struct/class đã được biên dịch cứng trong file binary C++/IL2CPP, iFix không thể nới rộng vùng nhớ của class có sẵn. Để lưu thêm biến trạng thái mới (ví dụ: timer đếm ngược, cờ bất tử, buff mới cho Actor), ta phải áp dụng mô hình State Extension Pattern sử dụng ConditionalWeakTable hoặc Dictionary<object, CustomState>.

5.3.1. Đọc và Kiểm soát Sinh mệnh & Sát thương của Actor (Actor Health & Damage)

Tình huống: Hàm tính sát thương trong game bị lỗi dẫn đến việc máu nhân vật có thể bị âm mà không kích hoạt hoạt ảnh chết, hoặc giáp bị tính toán sai. Chúng ta vá trực tiếp hàm nhận sát thương của ActorHealthComponent:

C# (Sửa lỗi HP & Tính sát thương) 
using UnityEngine;
using IFix;

public class ActorHealthComponent : MonoBehaviour
{
    public int currentHp = 1000;
    public int maxHp = 1000;
    public float armorDefense = 120f;
    public bool isDead = false;

    // Đánh dấu hàm cần ghi đè bằng IFix.Patch
    [IFix.Patch]
    public void TakeDamage(int rawDamage, int damageType)
    {
        if (this.isDead) return;

        // 1. ĐỌC THUỘC TÍNH: Lấy giáp và tính hệ số giảm thương thực tế
        float damageReduction = this.armorDefense / (this.armorDefense + 600f);
        int actualDamage = Mathf.Max(1, Mathf.RoundToInt(rawDamage * (1f - damageReduction)));

        // 2. GHI THUỘC TÍNH: Clamp máu trong khoảng [0, maxHp] để tránh bug âm máu
        this.currentHp = Mathf.Clamp(this.currentHp - actualDamage, 0, this.maxHp);

        Debug.Log($"[Hotfix] Actor nhận {actualDamage} sát thương. Máu còn lại: {this.currentHp}/{this.maxHp}");

        // 3. KIỂM TRA TỬ VONG VÀ KÍCH HOẠT SỰ KIỆN CHẾT CHUẨN XÁC
        if (this.currentHp <= 0)
        {
            this.isDead = true;
            this.TriggerDeathAnimation();
        }
    }

    private void TriggerDeathAnimation() { /* Logic phát hoạt ảnh tử vong */ }
}

5.3.2. Đọc và Cập nhật Vị trí / Tọa độ của Actor (Actor Position & Movement)

Tình huống: Sửa lỗi nhân vật bị kẹt xuyên tường (clip qua địa hình) hoặc cập nhật tọa độ đích di chuyển trong hệ thống điều khiển Actor:

C# (Kiểm soát Tọa độ & Di chuyển) 
using UnityEngine;
using IFix;

public class ActorMovement : MonoBehaviour
{
    public float moveSpeed = 5.5f;
    private static readonly Rect MapBoundary = new Rect(-50, -50, 100, 100);

    [IFix.Patch]
    public void MoveToDirection(Vector3 direction)
    {
        if (direction.sqrMagnitude < 0.001f) return;

        // 1. ĐỌC TỌA ĐỘ HIỆN TẠI: Truy xuất Transform của Game Object
        Vector3 curPos = this.transform.position;
        Vector3 nextPos = curPos + direction.normalized * (this.moveSpeed * Time.deltaTime);

        // 2. KIỂM TRA RANH GIỚI BẢN ĐỒ: Giữ nhân vật luôn nằm trong vùng hợp lệ
        nextPos.x = Mathf.Clamp(nextPos.x, MapBoundary.xMin, MapBoundary.xMax);
        nextPos.z = Mathf.Clamp(nextPos.z, MapBoundary.yMin, MapBoundary.yMax);

        // 3. GHI TỌA ĐỘ MỚI & ĐỒNG BỘ GÓC QUAY (ROTATION)
        this.transform.position = nextPos;
        this.transform.rotation = Quaternion.Slerp(
            this.transform.rotation, 
            Quaternion.LookRotation(direction), 
            Time.deltaTime * 12f
        );
    }
}

5.3.3. Thay đổi Hiển thị Hình ảnh / Icon Tướng (Render Hero Image & Dynamic Avatar)

Tình huống: Cần nạp động và render lại Sprite ảnh đại diện của Tướng trong UI mà không cần cập nhật lại bundle giao diện:

C# (Dynamic Sprite Rendering) 
using UnityEngine;
using UnityEngine.UI;
using IFix;

public class HeroAvatarView : MonoBehaviour
{
    public Image avatarImage;
    public Sprite defaultSprite;

    [IFix.Patch]
    public void UpdateHeroSkin(string heroId, int skinId)
    {
        if (this.avatarImage == null)
            this.avatarImage = this.GetComponent<Image>();

        // 1. TẢI TÀI NGUYÊN ĐỘNG: Tìm Sprite trong Resources hoặc nạp từ file cục bộ
        string resPath = $"Avatars/Hero_{heroId}_Skin_{skinId}";
        Sprite newSkinSprite = Resources.Load<Sprite>(resPath);

        // 2. RENDER HÌNH ẢNH: Gán Sprite mới và điều chỉnh tỷ lệ hiển thị
        if (newSkinSprite != null)
        {
            this.avatarImage.sprite = newSkinSprite;
            this.avatarImage.color = Color.white;
            this.avatarImage.preserveAspect = true;
        }
        else

using IFix;
using UnityEngine;

namespace NucleusDrive.Statistics
{
    public class CPlayerLocationStat
    {
        // Đánh dấu hàm cập nhật vòng lặp để vá logic đồng bộ
        [IFix.Patch]
        public void UpdateLogic(int deltaTick)
        {
            // 1. Kiểm tra trạng thái trận đấu
            var battleSystem = CBattleSystem.GetInstance();
            if (battleSystem == null || !battleSystem.m_isInBattle) return;

            // 2. Truy xuất GameActorMgr qua chuỗi phân tầng
            var battleLogic = BattleObjectBase.GetBattleLogic();
            if (battleLogic == null) return;
            var actorMgr = battleLogic.GetGameActorMgr();

            // 3. Lấy danh sách tướng (Heroes)
            var hostLogic = KyriosFramework.GetHostLogic();
            if (hostLogic == null) return;
            var heroes = actorMgr.GetCampHeroActors(hostLogic.GetEnemyCamp());

            // 4. Lặp qua danh sách và đồng bộ tọa độ / HUD pointer
            for (int i = 0; i < heroes.Count; i++)
            {
                var actor = heroes[i];
                if (!actor.HasValue || actor.GetHandle().IsDeadState()) continue;

                Vector3 pos = actor.GetHandle().GetLocation();
                var hud = actor.HudControl;
                if (hud != null)
                {
                    var pointer = hud.GetMapPointerSmall();
                    if (pointer != null)
                    {
                        hud.m_pointerLogicVisible = true;
                        if (!pointer.activeSelf) pointer.SetActive(true);
                    }
                }
            }
        }
    }
}

from Crypto.Cipher import AES
import struct, os

# 1. Tính toán MixedKey động theo tên tệp 'HeroSkin_2'
BASE_KEY = bytes.fromhex("99 64 b1 b0 6b 03 8d 7f b7 7d b6 a7 54 90 8b 73")
name = "HEROSKIN_2"
h = 0
for c in name: h = ((h * 31) + ord(c)) & 0xFFFFFFFF
k_parts = (h & 0xFF, (h >> 8) & 0xFF, (h >> 16) & 0xFF, (h >> 24) & 0xFF)
key = bytes(BASE_KEY[i] ^ k_parts[i & 3] for i in range(16))

# 2. Giải mã AES-128-CBC từ HeroSkin_2.bytes
with open("aov/HeroSkin_2.bytes", "rb") as f: data = f.read()
cipher = AES.new(key, AES.MODE_CBC, b"\x00" * 16)
decrypted = cipher.decrypt(data[8:])
orig_len = int.from_bytes(data[4:8], "little")
decrypted_bytecode = decrypted[:orig_len]

# 3. Kiểm tra Magic Header 8-byte InjectFix VM
magic = struct.unpack('<Q', decrypted_bytecode[:8])[0]
print(f"[✓] Magic Bytecode thô: {hex(magic)}")  # 0x1fd45f460e2cdbd0
with open("aov/HeroSkin_2.dec", "wb") as f: f.write(decrypted_bytecode)

Bước 3: Mã hóa AES-CBC thành tệp .bytes thành phẩm

Môi trường: Python Script AES-128-CBC

Trong Arena of Valor, tệp bytecode thô .dec không được phát hành công khai mà phải được mã hóa thành tệp .bytes để bộ nạp tài nguyên của game (ResDReader) xác thực, tránh bị can thiệp trái phép:

Sơ đồ chuyển đổi dữ liệu nhị phân (Data Transformation)
Tệp thô đầu vào (Input) HeroSkin_1.dec Magic: 0x1FD45F460E2CDBD0
encrypt_patch.py
Tệp thành phẩm đầu ra (Output) HeroSkin_1.bytes Header Magic: 22 4A 67 + Size
1
Băm & Trộn Khóa (MixedKey)

Băm chuỗi tên tài nguyên (HEROSKIN_1) qua hàm GetStrUpperHash, sau đó trộn với Base Key 16-byte qua GetMixedKey.

2
Mã hóa AES-128-CBC

Mã hóa toàn bộ nội dung bytecode thô bằng thuật toán AES-128 ở chế độ CBC với Initialization Vector (IV) là chuỗi 16-byte zero (0x00 * 16).

3
Đóng gói Header 7 Bytes

Chèn 3 byte Magic 22 4A 67 (dấu hiệu nhận diện mã hóa của AOV) + 4 byte kích thước gốc (Little Endian uint32) ở đầu tệp.

Bước 4: Tải và nạp bản vá tại Runtime qua PatchManager

Môi trường: Client Game Runtime PatchManager.Load()

Khi người chơi khởi động game, client tải tệp bản vá HeroSkin_1.bytes mới nhất từ CDN/Server về thư mục lưu trữ cục bộ (Application.persistentDataPath). Trình nạp tài nguyên giải mã và nạp trực tiếp luồng stream vào máy ảo iFix VM:

1. TẢI VỀ PERSISTENT

Lưu file .bytes vào thư mục có quyền đọc/ghi trên thiết bị (Android/iOS).

2. GIẢI MÃ MẬT MÃ

Game đọc header 22 4A 67, giải mã AES-CBC và mở luồng dữ liệu sạch.

3. KÍCH HOẠT HOOK VM

PatchManager.Load(fs) kích hoạt cờ is_patched, lập tức chuyển hướng thực thi sang VM.

C# — Script Quản Trị Nạp Bản Vá (HotfixManager.cs) 
using System.IO;
using UnityEngine;
using IFix.Core;

public class HotfixManager : MonoBehaviour
{
    void Start()
    {
        // 1. Xác định đường dẫn file bản vá trong thư mục lưu trữ cục bộ của thiết bị
        string patchFilePath = Path.Combine(Application.persistentDataPath, "HeroSkin_1.bytes");

        if (File.Exists(patchFilePath))
        {
            try
            {
                // 2. Mở stream tệp và nạp trực tiếp vào PatchManager
                using (FileStream fs = new FileStream(patchFilePath, FileMode.Open, FileAccess.Read))
                {
                    // Nạp bytecode vào máy ảo iFix; các con trỏ hàm gốc lập tức được hook sang VM
                    PatchManager.Load(fs);
                    Debug.Log(">>> [InjectFix] Nạp bản vá thành công! Tất cả hàm [Patch] đã được chuyển hướng.");
                }
            }
            catch (System.Exception ex)
            {
                Debug.LogError($">>> [InjectFix] Lỗi khi nạp bản vá: {ex.Message}");
            }
        }
        else
        {
            Debug.LogWarning(">>> [InjectFix] Không tìm thấy file bản vá cục bộ, game sẽ chạy code gốc AOT.");
        }
    }
}
